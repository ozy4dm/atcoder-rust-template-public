# 構造を比べる見本

同じ小さな運搬問題を3つの構成で書いています。特定の大会に依存しない練習用で、問題に応じて構成を選ぶための見本です。

| ファイル | 変更する対象 | 処理の流れ |
|---|---|---|
| `01_parameter_greedy.rs` | 貪欲の判断基準 | 重み→完成計画の生成→正式な評価 |
| `02_order_annealing.rs` | 完成した運搬順 | 交換→評価→受理／取り消し→最良計画を保存 |
| `03_beam.rs` | 複数の途中計画 | 集団を展開→評価→上位を残す |

共通の `delivery.rs` がルール・評価・操作列への展開を持ちます。探索側は運搬順を扱い、最後に「1歩進む／拾う／置く」へ展開します。障害物なし・1個だけ運べる・運搬間に追加制約がない条件の例です。置いた荷物が道を塞ぐ問題などへ、そのまま適用できるわけではありません。

作業フォルダ直下から実行する例：

```powershell
rustc --edition=2021 -O ahc-human/examples/02_order_annealing.rs -o order-example.exe
& ./order-example.exe
```

01・03も同様です。固定の小さな入力をプログラム内に持ち、順序・手数・操作列を表示します。順序の正しさと、評価した手数と操作列の長さの一致も確認します。最適解や改善を保証する汎用ソルバーではありません。

見本を読みやすく分割するため `mod` / `#[path]` を使っています。AHC Labと提出用freezeは単一ファイルが対象なので、実際に使う場合は必要な部品・処理を `main.rs` にまとめてください。見本をそのままLabの `source` に指定する使い方は想定していません。
