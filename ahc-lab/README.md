# AHC Lab：変更→10件確認→100件比較

Pythonの標準機能だけで動く、手元のAHCテスト環境です。追加のPythonパッケージやオンラインサービスは不要です。解答をビルドし、公式の採点ツールや対話型testerを起動します。

## 最初に使う

今後の大会ではリポジトリ直下から `python ahc-lab/new_contest.py <大会ID>` を実行し、作成された `contests/<大会ID>/open-lab.cmd` を開きます。解答・入力・ツール・提出版・結果はその大会フォルダにまとまります。既存のフォルダは上書きしません。必要なら `--port <ポート番号>` で画面のポートを指定できます。

`lab.json` の設定を終えるまでテストは無効です。大会が変わるときは共通コードを変更せず、新しい作業場所と設定を作るのが基本です。

作業フォルダ直下の **`ahc-lab.cmd`** をダブルクリックすると、動作デモの画面が開きます。デモは小さな品物選択問題で、AHCの得点を表すものではありません。


1. 変更メモを書き、**10ケース実行**を押す。
2. 結果を見て、解答ソースを修正・保存する。
3. もう一度10ケース実行。変更前の版を基準に選び、悪化したケースも見る。
4. 良さそうなら**100ケース実行**。同じ100件で試した版どうしを比べる。

終了は起動したウィンドウで Ctrl+C。途中の実行は画面の「停止」で終了できます。実行中にソースを変更しても、その実行は開始時に保存したソースと実行ファイルを使います。

## main.rsを編集し、提出用に連番保存する

ビルド・テストは引き続き設定の `source`（通常は大会フォルダの `main.rs`）を使います。「提出用に保存」を押すと、ファイルに保存済みの内容を `submission-001.rs`、`submission-002.rs` …としてコピーします。編集画面の未保存の内容は対象外です。

保存先は大会フォルダの `submissions/`。設定を省略した場合も、解答ソースと同じフォルダの `submissions/` に保存します。変更したい場合は設定に `"submissions": "保存先"` を指定します（`root` が基準）。

- 保存済みファイルを上書きせず、再起動後も最大番号の続きから採番します。同じ内容を再び保存しても新しい番号になります。
- メモ、保存日時、SHA-256、同じソースの完了済みテスト記録を同名の `.json` に保存します。テスト記録の一致はソースの一致で、コンパイル設定や実行引数まで同じことを保証するものではありません。
- 画面の一覧から表示・ダウンロードできます。保存後にファイルを手で変更した場合は変更を検出して表示します。
- main.rsは変更せず、ビルドやAtCoderへの提出も行いません。テスト設定前でも保存できます。

保存版をテストする場合は、一覧のそのファイルの行にある **「10件実行」「100件実行」** を押します。その保存版をビルド・実行し、履歴にファイル名を記録します。上部の実行ボタンは引き続き編集用ソースを対象とし、設定やmain.rsは切り替えません。保存後に変更が検出された版は実行できません。テスト後は一覧の「同じソースのテスト」も更新されます。

コマンドからも保存できます。以下の `$contest` は参加する大会IDを設定した変数です。

```powershell
python -X utf8 ahc-lab/lab.py freeze --config "contests/$contest/lab.json" --label "提出前の版"
python -X utf8 ahc-lab/lab.py run --config "contests/$contest/lab.json" --submission submission-001.rs --count 10
```

## 画面に出るもの

- 実行履歴：変更メモ、ソースのハッシュ、成功／失敗数、生得点合計、平均実行時間。
- スコアボード：表示中と入力・採点条件が同じ、全ケース成功の版だけに順位を付ける。
- 基準との比較：入力名と内容のハッシュが一致する共通ケースについて、改善量・勝敗を表示。10件と100件でも共通の10件は比較できる。
- 分類別の棒グラフと表：入力のサイズやパラメータ別に、生得点・改善率・実行時間・失敗数を表示。
- ケース一覧：失敗のみ／悪化のみの絞り込み、解答の出力・診断・採点ログへのリンク。

生得点は公式の相対スコアではありません。最小化・最大化は設定で切り替え、改善量はどちらもプラスが改善です。改善率は `(良くなった方向の差) / abs(基準得点)`。基準が0なら率は欠測、改善量は表示します。失敗を0点へ置き換えず、成功分の合計と失敗数を分けます。失敗や実行途中の版に総合順位は付けません。

## 大会が始まる前に用意する設定

作業場所の作成ツールが生成した `contests/<大会ID>/lab.json` を編集します。パスは `root` を基準に記述します。`root` 自体は設定ファイルの場所からの相対パスです。

| 項目 | 内容 |
|---|---|
| `name` | 大会名。大会が変わったら必ず変える |
| `source` | 自分の解答ソース。現在は単一ファイルを保存・ビルドする方式 |
| `inputs` | 公式生成器で用意した入力のフォルダ |
| `runs` | この大会の結果フォルダ。大会ごとに分ける |
| `direction` | 大きいほど良いなら `max`、小さいほど良いなら `min` |
| `build_command` | Rustなら既存例を利用。事前ビルドした実行ファイル／Pythonなら省略可能 |
| `solver_command` | 解答の起動方法。`{solver}` を必ず含める |
| `judge_command` | 公式vis等に入力と解答出力を渡すコマンド |
| `timeout_seconds` | ケースごとの解答実行の打ち切り秒数 |
| `judge_timeout_seconds` | 採点・特徴量抽出の打ち切り秒数 |
| `workers` | 同時実行数。初期値1。増やすと速いがCPU競合で探索結果・時間に影響する |
| `features` | 入力パラメータの読み取り位置と分類の境界 |

起動例（作業フォルダ直下から）：

```powershell
python -X utf8 ahc-lab/lab.py serve --config "contests/$contest/lab.json" --open
```

画面を使わず実行することもできます。

```powershell
python -X utf8 ahc-lab/lab.py run --config "contests/$contest/lab.json" --count 10 --label "評価の変更"
python -X utf8 ahc-lab/lab.py run --config "contests/$contest/lab.json" --count 100 --label "100件確認"
```

任意の件数も `--count 50` のように指定できます。入力が50件しかない場合、100件として重複実行せずエラーにします。最大100件です。

公式ツールの使い方は、参加する大会で配布されたREADMEを参照してください。初回に公式ツールをビルドするか、配布されている実行ファイルを用意し、その場所を設定します。以降は画面から解答のみをビルドします。

### コマンドの書式

コマンドは文字列1つではなく、引数の配列です。空白を含むパスも1要素にし、引用符を追加する必要はありません。シェルの `>` や `&&` は使いません。

- `{root}`：設定の基準フォルダ
- `{python}`：このツールを動かしているPython
- `{source}`：保存したソース
- `{binary}`：ビルドの出力先
- `{solver}`：保存・ビルドした実行対象
- `{input}` / `{output}`：そのケースの入力／出力ファイル
- `{case_dir}`：そのケースだけの作業フォルダ

解答はケースごとの作業フォルダで起動します。補助ファイルが必要なら絶対パスを引数に渡すなど、明示してください。複数ファイルのプロジェクトや外部データは自動で保存されません。Rustの `include!`、C++のローカルヘッダ、Pythonの隣接モジュール等を使う場合は、単一ファイル化するか、別途ビルドした実行ファイルを `source` に設定して `build_command` を省略します。

### パラメータを分類する

例えば入力の1行目の最初の値がNなら：

```json
"features": [
  {"name": "N", "line": 0, "token": 0,
   "bins": [30, 60], "labels": ["小：N < 30", "中：30 ≤ N < 60", "大：N ≥ 60"]}
]
```

`line` と `token` は0始まり。境界は下側を含み、30は中、60は大に入ります。分類の境界は固定です。実行ごとの分位点で動かさないので、10件と100件の分類が揃います。取得できなかった値は「取得不可」に分け、警告を表示します。

障害物率などを計算する場合は、任意の特徴量抽出プログラムも設定できます。

```json
"feature_command": ["{python}", "{root}/extract_features.py", "{input}"],
"features": [
  {"name": "障害物率", "key": "density", "bins": [0.2, 0.5]}
]
```

抽出プログラムは標準出力へ `{"density": 0.35}` のような数値のJSONを出します。抽出に失敗しても解答テストは続け、分類を欠測として残します。抽出コマンドと出力は実行記録に保存されます。

### 対話型

`configs/interactive.example.json` をコピーして修正します。これは設定の例で、そのまま動く解答は含みません。

```json
"mode": "interactive",
"solver_command": ["{solver}"],
"tester_command": ["{root}/tools/tester.exe", "{solver_args}"],
"score_stream": "stderr"
```

`{solver_args}` は解答起動コマンド一式へ展開されます。入力はtesterに渡し、解答へ直接渡しません。testerが残した出力をさらに公式visで採点したければ、`judge_command` を追加し、`score_stream` を `stdout` にします。

採点は既定では `Score = 数値` という1行を読み取ります。公式ツールが不正出力でも終了コード0・得点0を返す場合に備え、他の診断行を成功扱いしません。正当な0点は成功です。正当な追加ログがある場合だけ `judge_ignore_patterns` に行全体の正規表現を追加します。例：`["^DEBUG:.*$"]`。対話型では解答の診断もtesterの標準エラーに混ざることがあるため、解答側の診断行を `DEBUG:` などに統一します。全行を無条件に無視する設定は避けてください。採点形式が違えば `score_pattern`（第1キャプチャが得点）、`score_stream`、`judge_error_patterns` を設定します。

## 入力と記録

入力を名前順に並べ、100件以上なら全体から均等に100件選びます。10件はその100件から固定間隔で選ぶので、100件の部分集合です。入力集合を変えない限り、各版で同じケースになります。入力が特徴量順に並んでいる場合にも先頭だけへ偏りにくくしますが、10件で全分類を必ず網羅する保証はありません。

各実行の保存先は設定の `runs` 配下の `実行ID/` です。標準構成では `contests/<大会ID>/runs/実行ID/` になります。

- `source.*`、ビルドした解答：実行時のコピー。
- `result.json`：得点、失敗理由、特徴量、経過秒、入力と解答と採点ツールのSHA-256、設定、コマンド。
- `build.stdout.txt` / `build.stderr.txt`：ビルドログ。
- `case-NNNN/`：入力のコピー、解答出力、解答・採点ログ。visが生成するHTMLもここへ分離。

100件テストの順位は、同じ入力の内容と採点設定・採点ツール・同時実行数などが一致する版だけで比較します。比較はハッシュの一致する共通入力のみで、欠測を混ぜません。解答の引数の変更は版の変更として比較できます。動的リンク先や外部データ等、すべての実行環境を丸ごと保存する機能はありません。

## 確認状況

- 自動テスト：同一入力の比較、実行版の保存、正当な0点、不正出力なのに0点・正常終了する採点器、異常終了、時間超過、子プロセスの終了、停止、対話型の入力の分離、分類の境界を確認。
- 公式採点ツールとの接続も確認しています。大会ごとにコマンドとログ形式を設定してください。
- Windowsでの子プロセス管理は [Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) を使用。解答起動前に管理対象へ追加し、停止・時間超過時にtesterの子も終了させます。

このツールによるローカル計測はAtCoder環境の実行時間を保証しません。時間打ち切り型の解答では、同じ版でもCPU負荷によって得点が変わります。

## 利用範囲と安全性

- 実機で確認している環境はWindows・Python 3.14・Rust 1.98です。Pythonのコードは3.10以上を対象に書いていますが、他OS・他バージョンでの実機確認は行っていません。`.cmd` はWindows専用です。他OSではPythonコマンドで起動し、公式ツールの実行ファイル名も合わせてください。
- このツールは設定に書いたコマンドを通常の権限で実行します。隔離して安全化する仕組みではありません。自分で確認したコードと設定を使用してください。ローカルホストだけで待ち受けますが、起動するプログラム自体の通信は制限しません。
- 単一ファイルのRust・Pythonで確認しています。別言語や複数ファイルへの対応を自動で保証するものではありません。補助ファイル・外部ライブラリ・実行時データは別途設定してください。
- ケースの得点は有限値で絶対値2^53以下を対象にします。超える値は欠測にし、合計も画面の整数精度の範囲を超える場合は「精度範囲外」と表示して順位対象から外します。小数には浮動小数点の誤差があります。
- 保存版に表示するテストは同じソースの記録であり、同じビルド設定・引数での実行を保証するものではありません。
- 強制終了した記録がrunningのまま残る場合があります。完了扱いやスコアボードの順位には含めず、新しい実行で確認してください。自動再開の機能はありません。
